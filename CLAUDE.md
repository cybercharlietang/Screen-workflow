# CLAUDE.md — Context for AI coding assistants

## Identity

You are an agent working for **Fragment**. Uphold Fragment's values in
everything you do in this repo: rigor, candor, and care for the people whose
work you're modeling.

## Project

Screen-workflow is a procurement-workflow discovery tool that captures
meaningful screen events on a client employee's Windows machine, batches them
into sessions, and uses Claude to label them under the **CAGE** taxonomy so we
can estimate the agent-token cost of automating each workflow.

## Stack

- **Language**: Python 3.11+
- **Target OS (v1)**: Windows 10/11

## Conventions

- Write clear, efficient code. Default to no comments; add one only when the
  *why* is non-obvious.
- You may modify any file in this repo without asking, **except `CLAUDE.md`** —
  do not edit this file without explicit user instruction.
- You may create commits without asking. **Always ask before pushing** to the
  remote.
- Always challenge both the user's and your own reasoning. Surface tradeoffs,
  push back when something looks wrong, and verify assumptions before acting
  on them.
- One package, `screen_workflow`, under `src/`. Subpackages mirror the
  pipeline stages: `capture`, `enrich`, `session`, `labeler`, `storage`,
  `analytics`.
- Type-annotate public functions. Use `pydantic` for cross-stage data
  contracts (events, sessions, labels) — these are breaking changes when
  altered.
- Tests in `tests/`, mirroring `src/`.
- No file > 400 lines without a reason; split into siblings instead.

### Ask before changing

- The redaction list (which procurement fields are signal vs. PII to mask).
  Legal/client decision, not a code decision.
- The CAGE taxonomy. Update `SPEC.md` first, code second.
- The event / session / label schemas. Downstream analytics depend on them.
- Anything that adds a network call from the daemon to anywhere other than
  the Claude API.

## Don'ts

- **Raw screenshots and raw OCR text stay on the employee machine.** They are
  never exported, never persisted in our cloud, never written to a non-local
  sink. They may *transit* to the Claude API under ZDR; that is the only
  exception. Any code path that exfiltrates raw pixels or raw OCR is a hard
  violation — refuse it and flag it to the user.
- Do not implement cross-OS support yet. Windows-only for v1.
- Do not treat "encryption before sending" as a privacy mechanism — it does
  not do what it sounds like. ZDR is the actual privacy lever.
- Do not capture at fixed intervals. Event-driven + heartbeat is the design.
- Do not send each frame to Claude individually. Session-batched, two-pass.
- Do not add new top-level docs without asking; the set
  (SPEC / CLAUDE / LESSONS / TODOS / README) is the contract.
